# Main Document: NewGame

Статус: draft 0.1

Дата старта документа: 2026-08-19

Этот документ - главная точка сборки по игре. Он фиксирует только те решения, которые мы действительно приняли, и отдельно помечает гипотезы, которые ещё надо проверить в прототипе.

## 1. Что Уже Подтверждено

- Проект делается в Unity.
- Проект перешёл из 2D-направления в 3D-направление.
- Целевая игра строится вокруг идеи tower defense с merge-механикой.
- Визуальный стиль должен использовать 3D-модели.
- Камера должна показывать объём моделей, но не мешать видеть путь врагов.
- В репозитории уже есть первый prefab башни: `BaseTower.prefab`.

## 2. Рабочее Описание Игры

NewGame - 3D tower defense с merge-механикой.

Игрок размещает башни на поле, объединяет одинаковые башни для усиления и защищает базу от волн врагов. Враги движутся по заранее читаемому маршруту. Башни атакуют автоматически.

Ключевая идея: игрок должен одновременно думать о защите маршрута и о том, как эффективнее объединять башни.

## 3. Основные Принципы

Игра должна быть:

- читаемой: игрок всегда понимает, где враги, куда они идут и какие башни работают;
- тактильной: merge должен ощущаться как понятное усиление;
- компактной: поле не должно превращаться в хаос;
- mobile-friendly: управление и камера должны хорошо работать на телефоне;
- расширяемой: новые башни, враги и волны должны добавляться через конфиги и prefabs.

## 4. Камера

Текущий выбранный термин: **3/4 top-down orthographic camera**.

По-русски: **наклонённый вид сверху** или **ортографическая камера три четверти сверху**.

Это не классическая изометрия и не чистый вид сверху. Нам нужен промежуточный вариант:

- камера достаточно наклонена, чтобы видеть форму и высоту 3D-моделей;
- камера достаточно высокая, чтобы башни не перекрывали врагов и маршрут;
- ортографическая проекция помогает сохранить читаемость клеток, дистанций и поля.

Стартовая гипотеза для Unity:

- Projection: Orthographic
- Rotation X: примерно 55-65 градусов
- Rotation Y: примерно 35-45 градусов
- Framing: активное поле, маршрут врагов и база в одном кадре

Главное правило: если красивый ракурс мешает геймплею, побеждает геймплей.

## 5. Core Loop

Базовый игровой цикл:

1. Игрок получает стартовые ресурсы.
2. Игрок ставит башни на поле.
3. Враги появляются волнами и идут по маршруту.
4. Башни автоматически атакуют врагов в радиусе.
5. За уничтоженных врагов игрок получает ресурс.
6. Игрок покупает или получает новые башни.
7. Две совместимые башни можно объединить.
8. Более сильные башни помогают пережить следующие волны.
9. Игрок побеждает, если защищает базу.
10. Игрок проигрывает, если враги уничтожают базу.

## 6. Merge-Механика

Минимальное правило для первого прототипа:

- объединяются две башни одного типа и одного уровня;
- результатом становится башня того же типа, но следующего уровня;
- merge должен давать заметное усиление.

Что может усиливаться:

- урон;
- радиус атаки;
- скорость атаки;
- тип снаряда;
- количество целей;
- визуальный уровень модели.

Для первого прототипа достаточно одного типа башни и нескольких уровней.

## 7. Башни

Башня - основной инструмент игрока.

Минимальные параметры башни:

- id;
- название;
- уровень;
- prefab;
- цена;
- урон;
- радиус атаки;
- интервал атаки;
- тип цели;
- визуальная точка выстрела `FirePoint`.

Первый существующий ассет:

```text
Assets/_Project/Prefabs/Towers/BaseTower.prefab
```

## 8. Враги

Враг движется по маршруту к базе.

Минимальные параметры врага:

- id;
- название;
- prefab;
- HP;
- скорость;
- награда за убийство;
- урон по базе;
- размер коллайдера;
- высота точки для HP bar.

Для первого прототипа враг может быть без анимаций. Движение можно делать кодом. Анимации `Walk`, `Hit`, `Death` добавим позже.

## 9. Бой

Базовая логика боя:

- башня ищет врага в радиусе;
- первый приоритет цели: ближайший враг;
- башня стреляет с заданным интервалом;
- снаряд летит к цели или попадание считается при достижении цели;
- враг теряет HP;
- при HP `0` враг умирает и исчезает.

Первые боевые эффекты могут быть простыми. На старте важнее проверить читаемость и ритм.

## 10. Игровое Поле

Пока решение не финальное.

Рабочая гипотеза:

- отдельные клетки/слоты для башен;
- отдельный путь для врагов;
- башни не блокируют путь;
- база стоит в конце маршрута.

Нужно решить:

- сетка будет квадратной, ромбовидной или свободной;
- будет ли поле фиксированным или уровни будут отличаться;
- можно ли будет менять маршрут врагов;
- будет ли игрок строить только рядом с маршрутом или на отдельной зоне.

## 11. Экономика

Минимальная экономика:

- стартовая валюта;
- цена получения башни;
- награда за убийство врага;
- награда за волну;
- стоимость улучшений, если они появятся.

Цель экономики на старте - задать темп игры, а не монетизацию.

## 12. Волны

Минимальная волна:

- тип врага;
- количество врагов;
- задержка между врагами;
- пауза до следующей волны;
- награда за прохождение.

Для первого прототипа можно сделать одну повторяющуюся волну, которая постепенно становится сложнее.

## 13. Конфиги

Основной подход: **ScriptableObject-конфиги**.

Почему так:

- удобно редактировать в Unity Inspector;
- подходит для начинающего этапа;
- хорошо связывается с prefabs;
- позволяет не хранить баланс прямо в коде.

Первый набор конфигов:

- `TowerConfig`
- `EnemyConfig`
- `WaveConfig`
- `EconomyConfig`

Папка:

```text
Assets/_Project/ScriptableObjects/
```

## 15. Технические Решения

Подтверждено:

- Unity 6000.5.8f1;
- URP;
- Git;
- Git LFS для моделей, текстур, аудио и других крупных ассетов.

Нужно уточнить:

- портретная или ландшафтная ориентация;
- целевой FPS;
- минимальный Android-девайс;
- нужна ли поддержка offline-only;
- будет ли аналитика/реклама/IAP.

## 16. Первый Вертикальный Срез

Цель первого вертикального среза - доказать, что базовая игра работает и читается в 3D.

Минимальный состав:

- одна сцена;
- 3D-камера 3/4 top-down;
- поле;
- путь врагов;
- база;
- один тип башни;
- один тип врага;
- автоматическая атака;
- HP врага;
- смерть врага;
- простая покупка или выдача башни;
- merge двух башен;
- одна или несколько волн.

## 17. Открытые Вопросы

- Какое финальное название игры?
- Android остаётся основной платформой или меняем приоритет?
- Ориентация экрана: portrait или landscape?
- Башни покупаются конкретно или выпадают случайно?
- Merge происходит drag-and-drop или через кнопку/слот?
- Дорожка врагов одна или несколько?
- Враги идут строго по маршруту или по линиям?
- Нужна ли мета-прогрессия между уровнями?
- Какой визуальный стиль: low-poly, stylized fantasy, sci-fi, toy-like?
